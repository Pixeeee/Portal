# Hardware Acceptance — MVP

Use two clean Android installations on physical devices.

- [ ] 1. Both installations independently create Portals.
- [ ] 2. Each receives a unique public code.
- [ ] 3. A resolves B by public code.
- [ ] 4. QR scanning resolves the same Portal without automatically calling it.
- [ ] 5. Caller sends a connection request.
- [ ] 6. Receiver gets a realtime incoming request.
- [ ] 7. Receiver can decline.
- [ ] 8. Receiver can accept.
- [ ] 9. Both establish two-way live video.
- [ ] 10. Both establish two-way live audio.
- [ ] 11. Camera can be disabled/re-enabled.
- [ ] 12. Microphone can be muted/unmuted.
- [ ] 13. Front/back camera can switch.
- [ ] 14. Either side can end the session.
- [ ] 15. Session metadata appears in history.
- [ ] 16. Temporary network interruption enters reconnect and recovers when possible.
- [ ] 17. Disconnected Portal resolves as offline after presence TTL.
- [ ] 18. A Portal already in an active session returns Busy to a new caller.
- [ ] 19. Directionally trusted Portal can auto-accept with the visible 3-second cancel countdown.
- [ ] 20. No human login, role selection, employee profile, meeting ID, chat, social discovery, or recording exists.
